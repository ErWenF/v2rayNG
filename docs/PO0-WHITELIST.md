# v2rayNG Po0 白名单使用与验收说明

本功能在 v2rayNG 中维护 Po0 机器的防火墙白名单：查询当前 IPv4 出口，在缺少记录时补加，并提供定时检查、网络切换检查和可选独立服务。代理节点、订阅和 Po0 白名单凭证分别配置；加白成功后仍需正确配置节点、端口和服务端转发。

本文依据当前代码及官方教程编写。设备运行、真实 Token 和耗电验证尚未进行，具体未执行项目见文末；最终构建及自动测试结果由交付记录单独说明。

## 1. 安装与首次配置

### 安装与官方版迁移

Po0 分支 `2.3.11.2` 基于上游 v2rayNG `2.3.11`，使用包名 `com.v2ray.ang`。多数近年手机选择 `arm64-v8a`，不确定架构时选择 `universal`；最低系统为 Android 7.0／API 24。安装时选择相应版本的 APK 与 `SHA256SUMS.txt`，核对文件哈希；公开附件见[发布列表](https://github.com/ErWenF/v2rayNG/releases)。

本次使用 `PlaystoreRelease` 构建；五个 APK 已核对为 `debuggable=false`，沿用此前本机 Po0 构建的签名证书。证书主题名为 `Android Debug`，这与 Release 构建类型、应用是否可调试是不同信息。该证书不是上游官方证书，也不是新建的独立生产证书，SHA-256 指纹为：

```text
7ce6409774f34f0aa1b8f31212d970c0a7fbacb77dc11d8f76c46e466ac4e90c
```

**官方原版与本分支包名相同、签名不同，不能直接覆盖安装，同一 Android 用户下也不能并存。** 卸载会删除应用数据，首次迁移请依次操作：

1. 在原应用使用其已有导出或备份功能，保存节点、订阅、路由和设置；导出未涵盖的字段另行记录。
2. 将备份放到应用私有目录之外，例如电脑。打开并核对文件、条目数量及必要配置，确认备份可访问、内容完整后再卸载。
3. 卸载官方原版，安装选定的 Po0 APK。
4. 导入备份，逐项核对节点、订阅、路由和设置，必要时手动补齐。首次连接重新授予 VPN 权限。

官方版迁移、跨版本备份恢复与字段完整性均为 **Not run**，尚无设备验证，不能保证所有字段自动恢复。Po0 Token 应另行妥善保存；Android Keystore 加密记录不能依赖跨设备或卸载后自动恢复，重装后应准备重新填写。

后续覆盖升级需要保持相同包名、相同签名，且 `versionCode` 不降低；本次 APK `versionCode` 为 `4000753`。本版沿用 `2.3.11.1` 的 Po0 签名。升级前仍需备份并核对实际附件哈希、签名和版本。这些是覆盖条件，不能据此认定设备升级或数据保留已验证。

### 首次配置 Po0

1. 在 Po0 控制台打开相应机器详情，进入“防火墙”卡片，选择“复制添加脚本”，取得其中以 `pgnfw_` 开头的 Token。每台机器有各自的 Token。
2. 打开 v2rayNG 的“侧边菜单 → Po0 白名单”，点击“添加 Token”，填写名称及一台服务器的凭证，点击“完成”。名称可留空；推荐使用容易识别的名称，例如“家用服务器”。
3. 使用默认普通 FIFO 时，直接填写 Token；仅在需要固定记录时添加 `@0`～`@4`。重复添加可维护多台服务器，也可用“批量导入”一次导入多条，再逐条编辑名称。
4. 按需要开启“启用自动加白”和“网络变更时检查加白”，保留默认 600 秒检查间隔。
5. 需要关闭代理后继续维护时，同时开启“代理关闭后继续自动加白”。
6. 点击“保存”。有未保存修改时，先保存，再使用“只读查询”或“立即加白”。

关闭自动加白也需要点击“保存”才会更新正在运行的服务。Token 填写和手动操作不要求先启动代理。

每条 Token 可独立编辑名称和凭证、从本地列表删除。编辑器中的“完成”或“导入”更新页面草稿，页面下方的“保存”才会将所有条目与开关一起加密保存。删除本地 Token 不会删除服务器上的白名单 IP。

升级后，旧版保存的 Token 自动转换为独立条目，保留先后顺序、固定槽和设置；尚未命名的条目显示短标识，可逐条补充名称。旧版误将中文逗号／分号连接的多个 Token 保存为一条时，本版会在迁移中拆分合法凭证。

新版保存的命名配置不能由旧版读取；如需退回旧版，应准备重新填写 Token。

## 2. 支持哪些凭证输入

以下示例中的 Token 都是占位符，请替换为自己的凭证。应用只提取凭证文本，不会执行粘贴的命令或下载安装脚本。

| 输入形式 | 示例与说明 |
| --- | --- |
| 单个 Token | `pgnfw_example_a` |
| 多台机器 | 使用“批量导入”，每行一个，或填写 `pgnfw_example_a,pgnfw_example_b`；也支持中文逗号、中文／英文分号、空白、竖线和顿号。导入为独立条目，已有凭证保留原名称，重复凭证不再添加 |
| 固定槽位 | `pgnfw_example_a@0`；支持 `@0`、`@1`、`@2`、`@3`、`@4` |
| 官方配置内容 | `PO0FW_TOKENS="pgnfw_example_a,pgnfw_example_b@0"`，可包含空行和以 `#` 开头的注释行 |
| 官方查询链接 | `https://124.221.69.228/api/firewall/pgnfw_example_a` |
| 官方加白链接 | `https://124.221.69.228/api/firewall/pgnfw_example_a/add` |
| 带槽位的官方链接 | `https://124.221.69.228/api/firewall/pgnfw_example_a/add?slot=0`，保存后相当于 `pgnfw_example_a@0` |
| 官方命令片段 | 可粘贴含上述 API 链接的 `curl` 命令，或含 Token 的官方 OpenWrt、Linux、Windows 安装片段 |

官方安装片段的识别范围包含 `w0ven/po0fw` 的 `po0fw.sh`、`install-linux.sh`、`openwrt/install-openwrt.sh`、`windows/install-windows.ps1`，以及 `po0fw.uuuz.de` 的已支持入口。只有下载地址、没有 Token 的片段不能提供机器凭证；遇到格式提示时，可从脚本中复制 `pgnfw_...` 本身。

API 链接要求使用官方 HTTPS 地址，固定槽位参数只能是 `slot=0`～`slot=4`。输入普通 Token 或链接不会立即请求服务器；点击保存后，自动服务可能开始检查。

“添加 Token”与“编辑 Token”每次接受一条凭证；含多个 Token 的脚本或链接列表请使用“批量导入”。批量导入同样兼容混合填写裸 Token 与官方 API 链接。导入存在无效项时，保留输入供修正，已保存的条目不受影响。

## 3. 普通 FIFO 与固定槽位

官方白名单以来源 IPv4 的 `/24` 网段为单位。当前教程说明默认容量为 5 个网段，页面容量以服务器实际返回值为准。

| 模式 | 写法 | 行为与适用场景 |
| --- | --- | --- |
| 普通 FIFO，默认 | `pgnfw_example_a` | 当前网段不存在时补加；普通记录容量满后，由服务器按最早写入规则淘汰。适合手机、外出笔记本等流动设备 |
| 固定槽位，可选 | `pgnfw_example_a@0` | 将出口放入指定槽位，不参与普通 FIFO 淘汰。适合需要长期保留的出口；槽位可选 0～4 |

自动检查和“立即加白”都会先查询：当前网段已经满足所选模式时，不重复提交添加请求，避免无必要的写入。被其他设备挤掉的普通记录，可在后续检查时再次补加；多个设备不断争用有限名额时，仍可能互相挤出。

固定槽位号由你指定，`@0` 是 0 号槽位，不代表记录在列表中的排列位置。

指定槽位已有旧出口时，加白请求可以更新该槽位；当前网段原为普通记录时，可以请求转为指定固定槽位。因此，同一台设备切换到另一个网段后，使用同一固定槽位可能替换该槽位原有出口。应自行安排不同设备的槽位，避免共享一个固定编号互相覆盖。官方建议移动设备优先使用普通 FIFO。

同一网段已位于另一个固定槽位时，本实现显示“固定槽位冲突”，停止本次补加；先到 Po0 面板删除旧记录，再按目标槽位操作。更换槽位号或解除固定记录时，也应在面板核对和清理旧记录；只删除 Token 后缀不会替你删除服务端记录。应用不提供白名单删除按钮。

## 4. 只读查询、立即加白与结果列表

| 操作 | 对本次请求的作用 |
| --- | --- |
| 只读查询 | 读取机器白名单和当前出口，不提交添加请求，不占用新名额 |
| 立即加白 | 查询后，按普通 FIFO 或指定固定槽位补加当前出口；已满足条件时保留查询结果 |
| 自动检查 | 服务按定时或切网事件执行同样的“查询后按需补加” |

手动按钮使用已保存的 Token，在“启用自动加白”关闭时也可使用。**“只读查询”仅约束这一次手动操作，后台自动加白仍独立运行。** 需要只观察时，先关闭自动加白并保存，等待在途操作结束；其他设备或脚本仍可能同时维护这台机器。

每台机器优先显示保存的名称，未命名时显示凭证的短标识，并展示当前 IPv4、白名单条数与容量、执行状态，以及服务器返回的全部 IP／网段记录。查询和加白会处理全部已保存条目；单条请求被拒绝或返回无效响应时，其余条目继续执行并分别显示结果。名称根据凭证标识关联，修改名称或删除条目不会把结果对应到另一台机器。界面参考 Po0-clash：

- 按服务器返回顺序以标签展示全部 IP／网段，不添加列表序号。
- 高亮与当前出口匹配的网段，并显示定位图标。
- 普通记录标注“FIFO”；固定记录标注“固定 @N”，非当前固定记录显示图钉。
- `/24` 记录按网段匹配；兼容旧响应时，两条都为裸 IPv4 的记录按完全相同的 IP 匹配。

仅凭显示顺序无法确认 FIFO 淘汰排名，固定槽位号也不代表列表排列位置。

页面显示的是最近一次结果，并非持续实时探测。只读查询后看到后台更新的结果，或者切网期间仍看到上次的出口时，应结合“上次检查”时间判断。手动请求过程中切换或丢失物理网络会取消该批次，请待网络稳定后重新点击。

## 5. 自动维护何时运行

未开启独立服务时，自动维护跟随正在运行的代理服务；停止代理后不继续后台维护。要在代理关闭后继续运行，必须同时开启“启用自动加白”和“代理关闭后继续自动加白”，再点击“保存”。这会启动带“Po0 自动加白”通知的独立前台服务，不要求启动代理或授予新的 VPN 连接。代理与独立服务共用一套维护调度。

独立服务使用 `START_NOT_STICKY`。若独立服务或守护进程被系统杀掉，不能依赖系统自动重建；强行停止应用后同样不会继续维护。重新打开应用，确认两个开关已开启，再在本页点击“保存”显式启动。单纯重新打开页面不会代替保存。常驻通知提供“管理加白”入口；关闭独立服务开关并保存可停止这个后台所有者，代理仍运行时可继续由代理维护。

“网络变更时检查加白”会在可用物理网络就绪后进行短暂稳定等待，再尝试检查。关闭这个开关后仍有定时检查。Wi-Fi 不断开但公网 IP 悄然变化，通常要靠定时检查发现，不能只依赖切网事件。

请求绑定选定物理网络，并绕过应用代理和系统 HTTP 代理，设计目标是维护真实接入网络出口。上游路由器的透明代理、VPN 的“阻止未通过 VPN 的连接”等环境仍可能改变出口或阻断请求，应将页面的当前 IPv4 与 Po0 控制台核对。加白状态不等于代理连通性测试。

## 6. 定时与省电策略

- 默认间隔为 **600 秒（10 分钟）**，亮屏且未启用系统省电时可设 **1～3600 秒**。5 秒预设仅适合临时观察，会增加请求频率。
- 熄屏或系统省电时，后续周期至少 **900 秒（15 分钟）**；用户设置大于 900 秒时采用更长值。切网触发和显式手动操作仍是独立触发条件。
- 失败周期采用指数退避；退避上限为“当前基础间隔”和 1800 秒中的较大值，成功后恢复基础间隔。网络或部分临时服务端错误还会有有限次数的单次请求重试。
- 使用普通协程定时，不持有唤醒锁，不设置精确闹钟；设备深睡、Doze、系统后台限制或厂商省电策略可以推迟执行。这里的间隔不是精确唤醒承诺。
- 自动维护在 Android API 31 及以上使用被动的最佳匹配网络回调；API 24～30 使用 `requestNetwork` 兼容路径，可能额外维持物理网络，耗电表现需在目标设备测量。手动操作也会临时请求物理网络，结束后注销。
- 自动加白关闭并保存后，会释放专属网络监听和电源状态监听；页面可见时每 5 秒读取本地状态，离开页面后停止这项页面刷新。

这些是代码采用的节能措施，不能据此承诺后台永不被杀、固定时间内一定加白或具体耗电量。家宽需要持续维护时，可按官方教程将固定出口维护放在路由器，手机负责外出网络。

## 7. 凭证保存与常见状态

Token 与相关设置使用 AES/GCM 加密，密钥由本机 Android Keystore 保存。密钥不随普通文件备份迁移；跨设备复制加密记录、卸载后恢复旧数据等情况，不能保证重新解密。换机或重装时准备重新填写 Token，不要把应用备份当成唯一凭证备份。Token 相当于加白凭证，不应放入公开截图、日志或公开仓库。

| 页面状态 | 处理方向 |
| --- | --- |
| 当前网络尚未加入白名单 | 需要时点“立即加白”，或等待已开启的自动检查 |
| 服务器未启用白名单 | 到 Po0 面板确认该机器的防火墙服务状态 |
| 请求被拒绝 | 检查该机器的 Token 是否正确及仍有效 |
| 固定槽位冲突 | 到面板核对当前网段所在固定槽位，按前文处理旧记录 |
| 检查未完成 | 确认网络可用，待稳定后重试；TLS、后台限制或上游拦截也可能导致失败 |
| 设置已保存，但服务未能更新 | 设置已落盘，后台运行状态尚未确认；检查系统通知／后台运行限制后重试保存 |

## 8. 设备验收清单

下列项目均为 **Not run**：当前没有可用真机或模拟器，未使用真实 Po0 Token，也未测量耗电。编译、自动单元测试或静态阅读不能代替这些检查。

| 状态 | 待执行场景 |
| --- | --- |
| Not run | Android API 24、25 的 HTTPS/TLS 证书链与接口访问；API 24～30 的兼容网络选择与释放 |
| Not run | 多 Token、普通 FIFO、固定 `@0`～`@4`、已有普通记录转固定、同槽换出口及跨固定槽位冲突；与真实面板核对 |
| Not run | 完整 IP 列表、当前 `/24` 高亮及固定／FIFO 标识；空表、部分失败和容量满时的显示 |
| Not run | VPN、仅代理、root 三种模式的冷启动、重复启动、正常与重复停止、初始化中停止 |
| Not run | Wi-Fi／蜂窝切换、断网恢复、静默换公网 IP，以及切网等待与停止并发；手动请求切网取消 |
| Not run | 独立服务在代理关闭时启动和继续运行；重复保存、停止代理、系统杀进程、强停与重新保存启动 |
| Not run | 熄屏、省电、Doze 和厂商后台策略下的检查延迟、失败退避、网络回调释放；真实流量及耗电对比 |
| Not run | VPN lockdown、上游透明代理环境下的真实出口及失败显示 |
| Not run | Token 保存、进程／Activity 重建、重启、卸载和换机恢复；密钥不可用时的提示 |
| Not run | 命名 Token 的添加／编辑／删除、批量导入、保存后关页重开，以及从旧版覆盖升级后迁移；真实多台服务器的部分失败显示 |
| Not run | 小屏与软键盘、横竖屏、键盘／D-pad 焦点、TalkBack 朗读和当前网段标识 |
